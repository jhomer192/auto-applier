# Lessons

- Never `pkill -f "<shared exec pattern>"` (e.g. `dist/index.js`) on the VPS — the assistant bot `claude-bot.service` runs the same `node dist/index.js` line, so a broad match kills it too. Stop services via `systemctl stop`, or target a specific PID/cgroup, never a fuzzy pattern shared across units.
- Deploy instruction/config changes to the target BEFORE launching a run that reads them. The first xAI apply was launched while the old `CLAUDE.md` ("don't use raw Playwright, use the stealth engine") was still on the VPS, so the model avoided the MCP and rabbit-holed. `claude -p` loads `CLAUDE.md` at process start — order the deploy first.
- Don't fight ATS form widgets (react-select, hydration, dropdowns) with hardcoded Playwright selectors — let the thinking model drive the Playwright MCP and pick options by visible text. The stealth layer's `navigator` overrides also froze react-select hydration; vanilla MCP works and Greenhouse/Lever/Ashby don't captcha a plain browser on direct applies.
- This repo is PUBLIC and the applicant is a third party: never write his name, email, phone or resume text into a tracked file. profile.yaml is the single source of truth for identity (gitignored) — reference it, don't inline it, and don't copy it into .env either.
- Don't source a narrow mandate by sampling a board pool — search for the job by title, then find the employer and probe their whole board. A pool sample reports the market exhausted when most boards simply have no opening in that lane today; the pool should be a cache of what search already found (Jack, 2026-09-18).
- When a lane is "already a priority lane" but converts at zero, check the kill-list before adding keywords: EXCLUDE was eating the exact target vocabulary (clearance, audit, every engineer title) while the lane had no RMF/SOX/ISSO/ITGC words at all.
- A wave cannot be triggered from a Claude Code session by "messaging Discord": the hub drops bot authors unless DISCORD_PEER_BOT_IDS lists them, classistant is barred from #applications by its own system prompt, and lifting Jack's desktop session token is off-limits. Fire waves by arming data/auto.json + restarting applier-hub, or have Jack type in #applications (Claude for Chrome works there).
- After changing CLAUDE.md or wave_prompt.txt, clear the channel's session in /opt/applier-hub/data/discord_sessions.json before the next wave — a RESUMEd session keeps the pre-change context and will not re-read the manual.
- applied.py's lane argument must be the QUEUE lane, not the résumé that went out: an IT-support role applied to with the security résumé logs as lane=security and inflates the cyber share.
- Tell the résumé writer to name tools exactly as CANDIDATE FACTS names them; an invented parenthetical ("Wazuh (endpoint security/SIEM)") is what the Haiku QC gate rejects, and two rejections drop the apply to the untailored base résumé.
- Breezy does not 404 a closed posting: the page answers 200 saying "this position has been closed", so _alive() passes it. The board's /json drops closed postings, so absence from the listing is the liveness signal — check the board, not the page.
- applied.py check only reads applied.csv (wins), so a posting skipped for fit can be re-queued and judged the other way hours later. check now also reports a prior skipped/blocked outcome from apply_events.jsonl.
- Greenhouse serves job `content` HTML-ESCAPED, so stripping tags before html.unescape leaves the markup as literal text and defeats any regex needing two words near each other — the years gate was silently dead on greenhouse. Unescape first, strip second.
- Keep verify's --max-years at the same bar the brain judges by. Verify at 4 while the brain calls 3+ too senior means every 3-year posting is printed, opened in a browser and thrown away at 5-10 minutes each.
